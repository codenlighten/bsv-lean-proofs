# Conformance vectors

Generated FROM THE MODEL by the `vectors` executable (`Vectors.lean`): every
`expected` value is what the Lean definitions in `BsvLeanProofs/Splice.lean`
return, not an observation of an implementation. Regenerate with
`lake build vectors && vectors/regen.sh`, which writes each file under a
temporary name and renames it into place.

Each file's header has `version`, `rows` and `rows_sha256` (the SHA-256 of the
`cases` array serialized with sorted keys and no spaces), which changes exactly
when a row changes.

Row format (a common script-fixture format, with extra fields):

- `id`, `opcode`, `covers` (what the row is for), `theorems` (the theorems that
  say what an accepted row must return);
- `utxo`: the era of the output being spent; `spend`: always `chronicle`;
- `txHex`, `amount`, `scriptPubKey`, `flags`: the spend. The scriptSig is empty;
- `flagset`: the same flag word as a list of the node's flag names
  (`script_flags.h` without its prefixes), so that an implementation with its
  own flag numbering can map names and need not decode the word;
- `expected`: `OK` or a script error name without the `SCRIPT_ERR_` prefix;
- `expected_1_2_2`: what the model of bitcoin-sv v1.2.2 (x86 scalar build)
  gives for the same script, where `EQUALVERIFY` means 1.2.2 computes a
  different result.

A row whose `expected` is `OK` ends by comparing the whole resulting stack with
the model's result, so an implementation that accepts it has computed the same
values, not merely avoided an error.

Measured: a compiled bitcoin-sv v1.2.3 `VerifyScript` returns `expected` on
every row of every file (`difftest/vectors_oracle.py`). The rebuilt GoBDK
libraries return the same verdict on every row of `splice-v1.json` on x86_64
and on aarch64 under emulation (reported by an independent review, not rerun here).

Four rows (`OP_NUM2BIN-huge-…`) pad to one hundred million bytes. The model is
not evaluated at that size; their expectation is the theorem `opNum2Bin_ok`
and the row checks the length with OP_SIZE.

Run by other implementations (as reported by their authors, not rerun here): an
independent Rust interpreter agrees on all 10,824 rows of `splice-v2.json` and
`shiftnum-v1.json` after one fix the rows prompted (its default stack-memory
budget; the hundred-megabyte rows exposed it). Error names follow the node's
`script_error.h` enum; the node's own test table abbreviates some of them
(for example `SPLIT_RANGE` for `INVALID_SPLIT_RANGE`).
